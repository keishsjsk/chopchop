# Вырезание из середины видео

## Как это устроено

**Модель** (`core/video.py`). Клип хранит не одну обрезку, а то, что от файла оставлено:
внешние границы `start` и `end` минус вырезанные куски `cuts`. Один диапазон без вырезов — это
прежняя обрезка, поэтому старый код (`with_trim`, `Clip(path, info, start=…)`) работает без
изменений: миграция сводится к тому, что обрезка стала частным случаем. `Clip.ranges` даёт
оставленные диапазоны в исходном времени, `Clip.ghosts()` — удалённые участки (вместе с
обрезанными краями), `Clip.segments()` — оставленное, разделённое метками разрезов.
`VideoProject.flat_ranges()` — итог склейки: плоский список диапазонов по клипам в порядке
следования.

Правила: всё удалить нельзя; соседние и пересекающиеся диапазоны объединяются; диапазон короче
одного кадра (`1 / fps`) пропадает; вырез короче половины кадра не делается. Метки разрезов
(`splits`) — не диапазоны: разрез ничего не удаляет, он лишь делит оставленное на сегменты,
которые можно выбрать и удалить; метки внутри удалённого пропадают.

**Операции** (`SplitAt`, `RemoveRange`, `RestoreRange`) — неизменяемые объекты с `apply(project)`.
`VideoSession.cut(операция)` кладёт результат в историю одним шагом, поэтому отмена и повтор
работают на уровне операции. Повторная та же правка историю не засоряет.

## Интерфейс

- **K** — разрезать в позиции указателя. Клик по сегменту выбирает его, **Delete** вырезает
  (остаток сдвигается). Клавиши не конфликтуют с C, R, B, D, T, I, O и клавишами просмотра.
- **Shift + протягивание** по полосе выделяет диапазон, **Ctrl+X** (или Delete) вырезает его.
- Удалённые участки показаны заштрихованными «призраками»: клик по такому участку возвращает его
  (или отмена). То же с обрезанными краями.
- **Ctrl + колесо** — масштаб полосы до кадра, **стрелки** — по кадрам, итоговая длина в строке
  состояния обновляется. «Сбросить обрезку» возвращает клип целиком, без вырезов и разрезов.
- Значок режима резки рядом с масштабом (быстрая, точная, спросить) меняется кликом и
  соответствует настройке «Резка видео». Если выбрана быстрая, а на каком-то стыке нужна
  точная, значок становится предупреждением.

## Предпросмотр

Предпросмотр играет только оставленное и перепрыгивает через вырезы. Выбран перескок по
наблюдателю позиции плеера, а не EDL mpv: время в плеере остаётся временем исходного файла, и
полоса обрезки, ручки, ключевые кадры и метки не требуют пересчёта; правка вырезов не
перезагружает файл. Цена — короткий скачок на стыке (точная перемотка к началу следующего
куска); на паузе плеер не прыгает, поэтому кадры внутри выреза можно разглядывать. EDL дал бы
плавный стык, но превратил бы все времена в «времена итога», и каждая правка требовала бы
загрузки новой цепочки.

## Экспорт

**Быстрый режим** (копирование потоков):
- Один клип одним куском — обычная обрезка (`-ss`, `-to`).
- Вырезы из середины одного файла — **один вызов ffmpeg** с concat demuxer: диапазоны
  перечислены директивами `inpoint` и `outpoint` в списке `list.txt`, промежуточных медиафайлов
  нет.
- Склейка разных файлов идёт через общий контейнер: каждый клип копируется в mkv, затем куски
  склеиваются. Напрямую склеивать нельзя: у mp4 и mkv разные единицы времени, и concat demuxer
  портит метки времени (на проверке видео получалось вдвое короче). Это воспроизводит тест
  `test_fast_join_of_a_cut_clip_and_a_second_file_in_another_container`.
- При копировании начать можно только с ключевого кадра. Ключевые кадры читаются через ffprobe
  по пакетам (без декодирования), начало каждого диапазона привязывается к ближайшему ключевому
  кадру **не позже него** (`inpoint` ставится именно туда, иначе демультиплексор отдаёт лишние
  кадры до начала и на стыках получаются дубли). Привязка показана на полосе: метки ключевых
  кадров внизу, у каждого начала диапазона отметка и, где начало не на ключевом кадре, красная
  линия сдвига. На таких стыках быстрая резка помечена как требующая точной (предупреждение в
  значке режима и в диалоге экспорта).

**Точный режим** (перекодирование H.264): один вызов ffmpeg. Вход каждого клипа обрезан по его
внешним границам (быстрая перемотка), внутри `split`/`asplit`, затем `trim`/`atrim` с
`setpts=PTS-STARTPTS`/`asetpts=PTS-STARTPTS` для каждого диапазона, нормализация, `concat`. Метки
времени каждого куска начинаются с нуля, поэтому на стыках нет дыр и рассинхрона. Эффекты
применяются к результату склейки.

Режим выбирается настройкой `editor.cut_mode` (быстрая, точная, спрашивать при экспорте).
В диалоге экспорта выбор доступен только при «спрашивать».

## Что осталось

- **Времена показа текста и рисунков.** В этой версии текст и фигуры показываются на весь ролик
  (времени показа в модели нет), поэтому подгонять их при изменении сегментов нечего.
  Когда появится время показа, оно должно храниться во времени итога и пересчитываться
  `Clip.to_result`.
- **Smart cut** (перекодировать только кадры у границ, остальное копировать) не сделан: нужен
  разбор GOP, кодирование коротких кусков с теми же параметрами потока и аккуратная склейка
  по `concat`; выигрыш — быстрая точная резка. Возможное улучшение.
- Ключевые кадры читаются один раз на файл (кэш в памяти); для очень длинных роликов чтение
  может занять секунды (в фоне, интерфейс не блокируется).
